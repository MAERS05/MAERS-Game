# 技术架构说明 (Engine Architecture)

`games/sq-du/` 是一个**游戏类型**：其下 `basic/` 存放该类型的通用引擎，其余每个子目录都是一个具体游戏（目前为 `sq-du-prototype/`）。目录规则为 `games/<游戏类型>/<游戏>/`，其中「游戏类型」就是管理页里每个模块的「游戏类型」字段（`modules.json` 的 `gameType`）：新建模块时按该字段落盘，修改该字段会把整个模块目录迁移到新类型目录下。引擎被严格分层，保证了复杂博弈游戏的扩展性与易测性，整体遵循"逻辑与表现分离、状态修改流水线化"的设计哲学。

## 0. 目录分层与依赖方向

```
games/sq-du/
├── basic/                      类型通用层（不依赖任何具体游戏）
│   ├── base/                   constants / engine / resolver / timer / game-registry
│   ├── main/                   effect（效果管线）/ judge（裁判层）
│   ├── effect/                 timing、status-handlers、function/（通用状态效果）、ui/（状态图标）
│   └── 架构说明.md
└── sq-du-prototype/            具体游戏（第一个游戏）
    ├── sq-du-prototype.html    入口页
    ├── base/                   constants（扩展技能 ID/元数据）/ effect-handlers / game-profile
    ├── main/                   ui.js、player-profile.js
    ├── ai/                     AI 决策链与角色定制
    ├── skill/                  技能实现
    ├── avatar/ background/ music/ manuals/ 及游戏文档
    └── mobile-sq-du.css
```

**依赖方向只允许 `游戏 → basic`，basic 绝不 import 任何游戏文件。** 二者唯一的接缝是 `basic/base/game-registry.js`：

- 游戏在启动时通过 `registerGame({ effectDefs, effectHandlers, effectOrder, ai, customize })` 注入技能元数据、技能处理器、AI 调度与定制化钩子（见 `sq-du-prototype/base/game-profile.js`，由 `main/ui.js` 第一条本地 import 触发）。
- basic 层只在运行期（函数体内）读取 `EffectDefs` / `EffectHandlers` / `EffectOrder` / `GameHooks`，**禁止在模块顶层读取**。
- 游戏内部模块统一从自己的 `base/constants.js` 导入常量；它转出 basic 的通用常量，并扩展本游戏的 `EffectId`（通用状态 ID + 技能 ID）与 `EffectDefs`。

主要包含四大模块结构：

## 1. 裁判层 `main/judge.js` (JudgeLayer)
**定位**：纯粹的物理与规则核心（无状态的纯函数集合）。
- **职责**：不拥有任何持续性状态。它仅仅接收外部提供的一个特定「时间截面快照」，然后在内部铺设一条按动速降序的虚拟时间线（Timeline），并模拟出两人发生物理碰撞的绝对客观结果（造成了多少点数伤害、谁被谁格挡、谁成功闪避等）。
- **胜负判定**：所有胜负判定、同归于尽、处决逻辑均收敛于 `judgeGameOver`，输出唯一封包协议 `ResolveResult`。战终/处决/同归场景下仅更新 `clashName`，保留原详细战报（`clashDesc`）供 UI 展示。

## 2. 效果层 `main/effect.js` (EffectLayer)
**定位**：战术状态缓冲带与能力修饰器。
- **职责**：分为两大宏观生命周期：
  - `onPre`（裁决前的战前修饰）：把盘踞在玩家身上的各个 Effect（如锁链禁止闪避、力量加成伤害），编译重写成能丢给法官（Judge）判定的最终提交订单 `ActionCtx`。
  - `onPost`（裁决后的因果应用）：在法官判定出实质伤害后，触发特定被动（例如挨打就掉生命上限、或者受伤后叠加怒气），最终处理回合末机制（效果衰减、计时器递增）。
- **特点**：提供了极致的扩展能力。只需将新的规则配置注册进 `effect-handlers.js`，即可插拔式实现各种奇幻的战斗特质，而不需要改动引擎核心。

## 3. 总线与解析枢纽 `base/resolver.js` (Resolver)
**定位**：调度者与数据路由管道。
- **职责**：如同一位制片人，串联起 EffectLayer 和 JudgeLayer。它负责从 Engine 收到两名玩家的意图后开始处理：先丢给 Effect 进行 `onPre` 修改 → 捕捉增量（Flash Data）并塞入快照给 Judge → 接受 Judge 产出的 Timeline → 再丢给 Effect 进行 `onPost` → 将处理完毕附带上最终血量/精力计算的结果发送回 Engine。
- **特点**：处理特殊中断信号。如短路型的 `INSIGHT_CLASH`（识破废除回合）逻辑就在此判断并绕过常规战斗演算。

## 4. 引擎核心机 `base/engine.js` (Engine Controller)
**定位**：带状态的主从控制核心（State Machine Controller）。
- **职责**：维护整局游戏唯一且客观的主舞台（PlayerState）。包含回合滴答时钟（Tick Timer）、阶段状态机（配置期装备槽、三十秒死线、暴露期与结算动画期）。
- **即时模式**：引擎支持 `instant` 标记，开启后跳过回合开始/结束的 1s 延迟、装备期不启动计时器（手动关闭）、行动期缩短为 1s。通过 `startGame({ instant: true })` 启用，`skipEquip()` 提供手动关闭装备期接口。
- **特点**：提供所有供 UI 乃至外部（如网络模式）调用的动作 API。所有生命周期通过强类型的事件总线 `EventBus` 广播给外部表现层。

## 5. UI 与前端呈现（游戏层）`<游戏>/main/ui.js` / `.html`
**定位**：响应式视图。
- **职责**：它不干涉游戏逻辑，只倾听 `EventBus` 发来的消息，利用 `DOM` API 进行面板重绘。包含浮动的状态显示框、交手日志、三段式详细 tooltip 面板等。
- **技能选择器**：内置"简"模式按钮，一键切换为三列紧凑网格布局，隐藏描述文本，适合快速选技时使用。
- **特点**：能轻松实现前端录像回放与战局恢复（通过给它灌入历史事件流和状态快照）。

## 6. AI 层（游戏层）`<游戏>/ai/` (AI Decision Chain)
**定位**：分层的玩家行为模拟器。

```
ai-scheduler.js   ←  时机调度（决策期/洞察期/重决策期/即时加速）
  └── ai-base.js   ←  基础打分（精力阶段管控 + 双侧效果感知）
  └── ai-strategy.js ← 策略层（已知底牌/重决策克制）
  └── ai-judge.js  ←  决策构建
  └── ai-enhance.js  ← 通用场景底线约束
  └── ai-extra.js  ←  技能评分（B+T 双权重体系）
  └── sq-du-maes/ai-maes.js  ← MAES 专属技能池 + 场景约束
```

> AI 的打分逻辑（`ai-base.js`、`ai-extra.js` 等）直接引用了具体技能 ID，因此目前整个 `ai/` 归属游戏层，没有放进 `basic/`。待打分表改为数据驱动后，可将通用的调度/决策骨架上移到 `basic/ai/`。

### AI 即时模式加速
即时模式下，当玩家就绪后 AI 尚未决策时，引擎调用 `accelerateAI()`（定义在 `ai-scheduler.js`）取消当前长延迟，用 0.5~1.5s 短延迟重新调度决策。AI 基础决策时间不变，仅在玩家就绪后加速。

### AI 技能权重体系（B + T）
所有技能权重 = **基础权重 B（1.2~1.6）** + **场景调优 T**，基础浮动严格控制在 ±0.2，场景加成独立叠加，保证 AI 行为的多样性与可读性。

## 8. 新增一个同类型游戏

在 `games/sq-du/` 下新建一个游戏目录（与 `sq-du-prototype/` 平级），`basic/` 内的引擎直接复用，**不复制、不修改**。新游戏只需提供以下内容：

| 文件 | 说明 |
|------|------|
| `<游戏>.html` | 入口页面（HTML 结构、CSS，`<script type="module">` 指向 `./main/ui.js`）；公共资源以 `/font/...`、`/ui-all/...` 绝对路径引用，状态图标引用 `../basic/effect/ui/` |
| `base/constants.js` | `export * from '../../basic/base/constants.js'`，再扩展本游戏的 `EffectId`（展开 `BasicEffectId` + 技能 ID）与 `EffectDefs` |
| `base/effect-handlers.js` | 展开 `StatusHandlers`（通用状态，来自 `basic/effect/status-handlers.js`）并追加本游戏技能处理器 |
| `base/game-profile.js` | 调用 `registerGame(...)` 注入技能元数据、处理器、AI 钩子与 P1/P2 定制化 |
| `main/ui.js` | UI 交互层；第一条本地 import 必须是 `../base/game-profile.js` |
| `skill/**/*.js` | 新技能实现（`onPre`/`onPost`/`onPhase` 钩子），引用 `../../../basic/main/effect.js` 等 |
| `ai/` | AI 调度与技能评分、角色定制化 |
| 立绘 / 背景 / 音乐 / `manuals/` | 视觉听觉素材与说明书 |

```
games/sq-du/
├── basic/                              （类型通用引擎，所有游戏共用）
├── sq-du-prototype/                    （第一个游戏）
└── <新游戏>/
    ├── <新游戏>.html
    ├── base/{constants.js, effect-handlers.js, game-profile.js}
    ├── main/ui.js
    ├── skill/{attack,guard,dodge,...}/
    ├── ai/
    └── manuals/
```

游戏内文件通过相对路径引用 basic，例如：

```js
// games/sq-du/<新游戏>/main/ui.js
import '../base/game-profile.js';
import { BattleEngine } from '../../basic/base/engine.js';
import { EffectLayer }  from '../../basic/main/effect.js';
```

### 玩家定制化

玩家技能库由 `createPlayerState()` 按 `EffectOrder`（即游戏注册的 `effectOrder`）扫描 `EffectDefs` 自动填充（过滤 `aiOnly: true` 项）。P1/P2 的数值定制化通过 `registerGame` 的 `customize.p1` / `customize.p2` 注入（参见 `sq-du-prototype/main/player-profile.js` 与 `ai/sq-du-maes/ai-maes.js` 的 `applyCustomization`），引擎在创建或重置玩家状态后自动调用。
